## 0. What you are building, and the rules

DuoView is a UEVR fork (rendering method ID6). It renders a centre-camera **fovea** and **periphery** and synthesizes both eyes per pixel by an inverse warp: `source = base + k_e·D(source)`, where D is a conditioned inverse-depth field (larger = nearer). M3a (the base) added per-eye conditioned depth (a 2-slice array), one-sided occlusion edges, background fill and a jitter-sign switch.

M3b adds **six independent features**. Each has its own switch, and **every switch defaults OFF**.

## 2. P1: Jitter direction, measured, with "Auto"

**Why:** DLSS shifts the camera by a sub-pixel jitter each frame. Our depth is DLSS *input* (jittered) and our colour is DLSS *output* (unjittered). If the sign of the correction is wrong, edges flicker. M3a only added a manual +/− switch.

- **Setting:** extend `DuoM3JitterMode` with value **3 = Auto**. 0, 1 and 2 keep their meaning.
- **New compute kernel `CSJitterScoreM3b`:**
  - Dispatch it only when the mode is Auto, after the analysis pass.
  - Over the fovea crop, on every 4th grid row, for each sign s ∈ {−1, 0, +1}:
    - sample coarse depth (nearest) at `uv + s·M1Eye.zw`;
    - compute e_d = |D(x+1) − D(x−1)| / max(D, 1e−4);
    - sample the source colour (the same texture the raster uses for that region) and compute luma gradient e_c = |L(x+1) − L(x−1)|;
    - add `uint(e_d·e_c·4096)` to counter[s].
  - Use a groupshared reduction, then `InterlockedAdd` into a small UAV.
  - Read it back through the **same ring as `m25_take_gpu_window`**: extend that window from 9 to 12 values, and update every user.
  - You will need to add the source colour SRV to the compute descriptor table. Keep the existing order and append the new one.
- **CPU logic:**
  - Accumulate 120 frames per window.
  - A window votes for the sign with the highest score, but only if that score is ≥ 3% above both others **and** the mean |jitter| is > 0.05 pixel. Otherwise the window abstains.
  - Switch the active sign only after **2 consecutive** votes for it. Start at +1.
  - Fine jitter uses the same sign.
  - Write the active sign into `M3Flags.y`.
- **Log** once per window: `[DuoView][M3b] jitter score minus=.. zero=.. plus=.. active=..`.
- **WARP proof test:**
  - Build a fixture where coarse depth has a step at column c + j·32, while the source colour has its step at column c. Set the input jitter so that sign +1 is correct.
  - Run 2 windows. Use a test hook to shorten the window to 4 frames, e.g. a `static` window-length override used only by the fixture.
  - Assert: the scorer picks +1, and with +1 the conditioned-field edge lies within 1 grid texel of c, while with −1 it is farther away.
  - Repeat with the colour step on the other side, and assert that −1 is picked.
  - This proves the measurement and the plumbing. The real game's convention is then decided by Auto and visible in the log.

## 3. P2: Temporal depth stabilization (flicker that remains)

- **Settings:**
  - `DuoM3bTemporal` (bool, OFF);
  - `DuoM3bTemporalStrength` (0.0–0.9, default 0.6).
- **Restructure, active only when ON:**
  1. New kernel **`CSSeedM3b`**. It writes the fused seed (coarse plus gated fine, jitter-corrected, exactly what `CSConditionM1` computes before its envelope) to `SeedTex` (R32_FLOAT, grid w×h). Factor the seed math into one function used by both kernels, without changing its expression order.
  2. New kernel **`CSStabilizeM3b`**. For each texel:
     - map the texel's centre-view UV to the previous frame with a rotation-only homography `HPrevFromCur` (3×3 in the cbuffer);
     - read the previous result from `History`. Take the 2×2 texels and pick the **one closest in value to the current texel**; never average them;
     - clamp it to [min − 0.002, max + 0.002] of the current 3×3 neighbourhood;
     - output `lerp(cur, clamped, strength)`.
     - Use `out = cur` when: the previous UV is outside the grid; history is invalid; it is the first frame; the layout, grid size or settings changed; or the rotation delta is > 10°.
     - Write the result to `Stabilized`.
  3. `CSConditionM1` and the vertical pass read the seed from `Stabilized` instead of computing it.
  4. History is ping-pong: two textures, swapped on the CPU each frame. Insert UAV barriers between the passes.
  - Name every new D3D12 resource (the repo uses `SetName` / its naming helper for DuoView resources; follow the M3a code).
- **`HPrevFromCur`:**
  - Formula: `K·R_prev⁻¹·R_cur·K⁻¹`, where:
    - K is the centre render's pinhole projection, mapped to grid UV; use the same tan-half-FOV and crop that DuoView uses to place the source;
    - R is the centre (cyclopean) view rotation of the frame **whose depth is being used** (the same frame and epoch as the depth packet).
  - If the frame packet does not carry this rotation, add a quaternion field where the centre view is produced, and pass it through with the depth.
  - Log the per-frame rotation delta in degrees, in the M3b log line.
- **Why there is no lag or ghosting:** the clamp means a moving object (gun, hands) can never keep old depth outside what the current frame shows around that spot. This is the TAA neighbourhood clamp.
- **Numeric model (Python), must pass:**
  - static noisy depth (σ = 0.01): variance falls by ≥ 40% at strength 0.6;
  - a step moving 3 texels per frame: output error ≤ 0.002 + 1 frame of motion (no trail);
  - a camera cut resets.

## 4. P3: Joey's edge repair (all other edges)

- **Settings:**
  - `DuoM3bEdgeRepair` (bool, OFF);
  - `DuoM3bEdgeRepairMask` (bool, OFF; debug colouring).
- **Source to port:** `AnalyzeSpatialRepair` in `joeyhodge/UEVR@5ac7edc`, `src/mods/vr/d3d12/DIBRPreview.cpp` lines 105–184, with constants `repair_residual_pixels=1.5`, `repair_depth_threshold=0.01` (lines 1679–1682).
- **Adapt it to DuoView,** in the raster, per eye, after the bisection and after `M3FillHole`. Skip it if the fill already moved the UV.
  - `target_depth` = this eye's conditioned depth at the final root. `source_depth` = raw source inverse depth at the final source UV (fine where fused, else coarse).
  - Low confidence when the root was clamped to lo/hi, **or** |target − source| > max(0.01, 4·local gradient).
  - Search direction: toward the **background**, meaning lower inverse depth (reuse M3FillHole's direction logic). Joey's displacement sign only works for his right eye.
  - Walk 1–8 source texels (texel = 1/grid_w). Accept the first position with a stable 3-sample background run (`IsDepthRunCompatible`) that is farther than the near side. Inside that run, pick the farthest sample, exactly as Joey does.
  - Remember that DuoView depth is inverse: "farther" means a **smaller** value.
- **Mask:** blend repaired pixels toward red, and low-confidence pixels that were not repaired toward yellow (Joey's colours).
- **Numeric model:** it never selects a foreground (larger) value; it finds the background within 8 texels; and it leaves a smooth slope alone.

## 5. P4: Colour-guided depth edges

- **Setting:** `DuoM3bColorEdges` (bool, OFF).
- In the seed computation, where coarse (and fine) depth is read at the jitter-corrected position:
  - Take the 2×2 nearest depth texels.
  - If max − min > 2% of max: sample the source colour at each candidate texel's centre and at the sample position, then pick the candidate with the smallest RGB L1 colour difference.
  - Otherwise take the **source-nearest** texel.
  - **Never average** across an edge.
  - Do not use "nearest surface wins"; it fattens the weapon.
- **Numeric model:** at a two-colour edge it returns exactly one of the two depths, and it picks the side the colour matches.

## 9. FXC SM5 checklist (CI compiles; preflight does not)

- **Groupshared:** ≤ 32 KB per entry point. The current file declares about 26.6 KB in total. Prefer separate small arrays per kernel.
- **Barriers:** `GroupMemoryBarrierWithGroupSync` only in uniform flow (conditions on cbuffer values or loop counters only). Never place it after an early `return`.
- **Typed UAV loads:** only R32_FLOAT, R32_UINT or R32_SINT; never R32G32.
- **Index types:** use `uint` consistently, and cast explicitly before mixing.
- **Sampling:** `SampleLevel` in compute shaders, never `Sample`.
- **Resource declarations:** every new texture, UAV or SRV must match the C++ view dimension (Texture2D vs Texture2DArray) and the root table order.
- **Fixture C++ checks** (MSVC, Windows only): the names exist in the fixture source; no lambdas capturing by reference outlive their scope.
