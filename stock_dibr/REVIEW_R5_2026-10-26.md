# R5 adversarial review corrections

Scope: Joey baseline DIBR and DIBR Single View for STALKER 2. No DuoView implementation. Backend, SDK and frontend pins remain unchanged from R4.

The user requested adversarial review and fixes. R4 had already passed 41 original compatibility tests and its Windows WARP fixture, but those checks did not cover the failure and lifecycle interleavings below. Terra was unavailable in the model runner and was not run. The current correction pass uses a Luna 6 max worker and a Sol 6.1 medium reviewer.

| Finding | Correction / disposition |
| --- | --- |
| Fallible allocations after GPU recording began left stale commands and resource references on a failed frame. | Prepare preview/descriptors/presentation first; close and discard abandoned recordings; hold source references through actual retirement. |
| Void submission failures still published output and readiness. | Checked submission result distinguishes no submission, tracked submission, event polling and untracked in-flight work. Publish only a proven usable output. |
| Failed producer/consumer depth Signal could be treated as an unsubmitted recording by list Reset. | Quarantine all affected submitted slots; retain them across Reset and mode exit. Regression exercises production capture with injected Signal failure. |
| UI footprint alpha depended on edge guard. | Supply alpha for the OR of all three independent consumers. |
| Cached descriptor replay could overwrite a concurrent newer update. | Serialize replay and publication; concurrent regression uses the production metadata helper. |
| Callback arrival order could differ from actual same-queue enqueue order. | Serialize enqueue plus callback by canonical native queue identity; independent queues remain concurrent. |
| Detach prevented pending generations from receiving retirement events. | Shared retirement hub continues late Execute/Reset callbacks, and collects only after retirement. |
| Destructor/observer detach could retain an armed owner or race a loaded raw observer. | Detach drains active observer callbacks; component teardown resets/disarms capture ownership. |
| Readiness could survive a UWorld replacement. | Invalidate before constructing views in a changed world; existing family stability checks remain. |
| Capture default enabled outside intended test setup. | Restore opt-in default; README instructs explicit enablement. |
| Same-size secondary-camera depth lacks semantic family identity. | Unresolved runtime boundary. Add bounded distinct-source diagnostics; do not claim viewport/queue proof identifies the camera. |

## Verification scope

The overlay is reapplied from a clean pinned backend. Linux policy checks run locally. The Windows workflow runs the production shader and capture fixture on WARP, concurrent hook fixtures, shared transaction fault-injection fixtures, the 41 original compatibility tests, full backend and injector builds, then packages the exact built files. Windows outcomes are recorded in the matching workflow evidence, not assumed here.

The standalone transaction fixture uses the production shared phase/output-state helpers with real WARP resources, rather than the entire CommandContext/D3D12Component integration. Full production integration is compiled by the backend build. Game camera identity, actual Streamline/runtime behavior and headset stability remain in-game validation boundaries.
