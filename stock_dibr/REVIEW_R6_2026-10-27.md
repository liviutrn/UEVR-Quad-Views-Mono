# R6 support review — 2026-10-27

## Scope

R6 adds depth inspection and calibration controls, optional isolated-spike
repair, candidate selection, and a UI for full rendering-mode comparisons. The
workflow applies the R6 shader stage after all eight R5 stages, then applies
the R6 UI stage. The shader stage copies `CandidatePolicy.hpp` into the
generated backend, where `StockDibrDepth.hpp` includes it. Backend, SDK, and
frontend pins remain unchanged.

The existing reprojection-strength default remains 1.0. The R6
“Preserve Stereo Strength” option defaults on for the STALKER 2 scope and
bypasses legacy edge stabilization, UI edge/footprint blends, and legacy color
repair while retaining the configured reprojection-strength value. The
optional max-strength button sets 2.0 only when pressed. Comparison buttons
request normal full rendering-mode transitions and require warmup; they do not
provide same-frame A/B output or change the saved Native Stereo Fix,
convergence, or strength settings.

Depth Scale defaults to 1.0 and adjusts device-depth values; it is not metric
depth calibration. Display exposure affects visualization only. Sampling
defaults to R5 linear, with point and edge-aware alternatives. Isolated-spike
median repair is off by default and requires coherent neighboring samples.
Raw and readable depth views render the same image to both eyes. Reprojection
confidence reflects the inverse solve and is not a visibility buffer or hole
mask.

## Candidate boundary

Candidate IDs are bounded resource identities for sources that passed capture
and producer-proof checks. They include copied size/format metadata and current
fresh-slot availability. The registry may evict only the least-recently-seen
entry older than the incoming observation and not manually selected. If no
such entry exists, new observations are rejected. IDs are not reused on
eviction or reset. A manual ID fails closed while its candidate is unavailable;
a capture reset invalidates old IDs and returns selection to automatic mode. A
same-size secondary camera can still pass the existing shape, binding,
viewport, and queue checks; candidate IDs do not prove semantic camera
identity.

## Adversarial corrections before Windows CI

Terra found manual selection could lose all capture slots to earlier unrelated
passes; capture now skips nonselected resources before allocating a slot, while
retaining execute-time provenance checks. The candidate registry evicts old
unselected entries without reusing IDs and releases their metadata COM retention;
in-flight slot references remain fence protected. Reset clears selection to Auto.
An invalid executed producer layout is rejected rather than reaching acquisition.
R5 linear sampling remains the default. Sol added production DepthCapture pixel
readback tests for manual selection, quota isolation, missing selections, reset
and reacquisition, alongside shader inspector/filter/repair/strength oracles.
These tests require the matching Windows CI run; their presence is not a pass.

First Windows CI attempt caught the Windows `max` macro expanding the portable
policy numeric limit call and an MSVC prohibition on passing a 256-byte aligned
test constant block by value. Both were corrected; the WARP shader now also uses
the production optimization level. No installable artifact came from that run.
