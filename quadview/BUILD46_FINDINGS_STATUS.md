# Build 46 review findings and status

Build 46 is the reviewed four-source ID7 implementation for STALKER 2 on UE5.5, DX12, OpenXR and PSVR2. It starts from accepted Build 40 source `7486fc59890b14673cd50770b0dafeb692576716`, preserving its FOV, gaze and crop behavior. ID7 renders four independent engine-owned sources (left/right context and focus) and composites separate images for each eye through ordinary stereo OpenXR submission. ID6 DuoView remains unchanged.

The final source revision is `af215afd3a0a624d9c1878e96e836fa9fbf26a4d`; the host build-workflow revision is `fe48ebf9deb14dc88c28e163bb81b612fc96d84a`. These are the exact revisions pinned for Build 46. The first Windows run, [39681187906](https://github.com/liviutrn/MUSE-UEVR-DUOVIEW/actions/runs/39681187906), passed the rendering suites but failed production compilation because the source overlay did not export `QuadViewFamilyRouting.hpp`. The export and a source-checkpoint regression were repaired. The final pinned workflow run, [39687797421](https://github.com/liviutrn/MUSE-UEVR-DUOVIEW/actions/runs/39687797421), completed successfully with all 31 workflow steps successful and no failed steps.

## Findings and production changes

| Sol review finding | Build 46 change | Evidence |
| --- | --- | --- |
| Distinct native callbacks can resolve to the same deferred Slate command tail. The inherited pointer-bit test was parsed so it always returned false; globally switching to a direct path would be unsafe. | The ID7 path brackets worker execution with explicit thread-local drain and immediate-list identities. A native batch records the roles actually attached to the tail, so a partial shared-tail quartet can complete on later tails. Cross-quartet or otherwise ambiguous sharing remains drainable but cannot publish. The callback retains the owners through the original tail call, including across ledger reset. Runtime cadence is claimed once from the newest represented view-3 event; an ambiguous batch may drain and advance that cadence, but cannot make its source selectable. | NativeDelivery tests cover partial shared tails, distinct later tails, ambiguous sharing, missing and late callbacks, one-time cadence and queued-owner lifetime. |
| Selecting the first family from the engine's `TArrayView`, or filtering every auxiliary family, can select the wrong family or suppress unrelated work. | The router authenticates a unique main family using the frozen family, scene, target and four view identities. It preserves the original first batch, including auxiliary families, then routes selected main-family singletons to later callbacks. Unrelated auxiliary families, including empty scene/target identities, pass through. Ambiguous or malformed potential main families fail closed. The routing helper authenticates the saved snapshot before mutation and restores the original view array and target on failures and exceptions. | FamilyRouting tests cover exact identity, auxiliary ordering, null identities, malformed and duplicate candidates, nested callbacks, first-registration failure, exceptions and restoration. |
| A late physical write from an older packet can overwrite part of a newer packet while that newer packet remains selectable. Callback attachment order does not prove GPU write order. | Per-target content stamps identify the packet that actually wrote each native output. Selection requires all four current target stamps to agree. An actual later writer invalidates stale proofs; a queued future quartet is not poisoned before it writes and can recover once all four of its outputs are written. Stamp records are reclaimed only when no live native owner uses their targets. | ContentProvenancePropertyTests check all 40,320 write orders across two quartets, compare every selected packet against reference target contents, verify coherent fresh-quartet recovery and exercise 40 target-set replacements without reset. |

Review also caught two ownership and dispatch cases during implementation. A tail-map entry must keep each represented source packet alive until the queued CPU-side RHI callback returns; a weak-pointer test confirms the execution lease is the sole owner across reset and releases the packet afterward. If slot-zero registration fails, the original family callback still runs once, but later singleton callbacks stop; the adapter restores the original batch and records the failure. Source-ledger fallback is drain-only, so it cannot publish a legacy atlas as a native quartet.

The replacement Windows run closed the compile-and-test gate. The local Linux validation remains useful for targeted stress and sanitizer coverage; the Windows run supplies the production build, WARP and compatibility evidence.

## Acceptance boundary and next steps

Windows CI and package verification are complete for source `af215afd3a0a624d9c1878e96e836fa9fbf26a4d`. The evidence source audit leaves `full_backend_compatibility_verified` and `headset_stability_verified` false. The 41 passing compatibility CTests and successful production build do not prove full runtime integration or in-headset behavior.

No headset trace or Build 46 headset test has been supplied. Display-gamma parity, in-game shading and shadows, live GPU-fence retirement, performance and headset stability remain unmeasured. The next acceptance step is testing the package in the target game and comparing a shadowed interior, both eyes' context/focus boundary, brightness and shadows, stereo depth, horizontal FOV, gaze movement, startup, repeated mode changes, save loading and sustained gameplay. Keep the Build 40 installation for comparison and retain the complete log if a check fails.
