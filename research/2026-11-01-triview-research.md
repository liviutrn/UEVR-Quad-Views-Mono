# TRI-VIEW DONE RIGHT — evidence audit and implementation research
**Date:** 2026-11-01 | **Branch:** `experiment/triview-research-20261101` | **Scope:** research only; no implementation, build, or headset test.

## Ten-line summary for Liviu (plain words)
1. **[headset-verified, user report]** AFW is abandoned: speed was acceptable but flicker, inconsistent motion and image quality failed against native stereo with 30→120 frame generation.
2. **[source-read]** The next experiment is three *real renders*: left sharp centre, right sharp centre, one shared low-resolution full-field background.
3. **[source-read]** Build 51 already contains the hard machinery to render independent views with Native Fix-style lighting and safely own the resulting textures.
4. **[source-read]** The previous tri-view B1/B2 shared background was only geometrically correct at infinity; B2 also used the wrong projection for the left sharp centre.
5. **[CI-verified]** B3 compiled successfully, but **[headset-verified, user report]** its picture was still broken: a successful compile was not a proof of alignment.
6. **[source-read]** To fix the proportions, use each eye's *original* projection and real camera, and shift each depth-backed background surface into both eyes before blending.
7. **[source-read]** Old synthetic stereo repeatedly changed between different camera images at edges; its fallback caused doubled hands, so do not copy that fallback design.
8. **[estimated]** Prefer the **Build 51 render-delivery base**, with carefully ported v207 convenience features and the useful CI82 reprojection primitives, not its whole rendering mode.
9. **[estimated]** Expect roughly the old B3 performance range, not a miracle: adding depth synthesis costs GPU time; stability and border alignment decide success.
10. **[estimated]** Build only three headset-testable stages. If normal play still flickers/smears in the periphery, stop; DuoView Mono v207 remains the product.

## 0. Evidence standard and audit boundary
- **[source-read]** Means exact repository source, commit diff, or written project/review record inspected. A project brief's report of a headset result is *not* a new independent measurement.
- **[CI-verified]** Means the linked GitHub Actions run metadata reports success for its exact `head_sha`. CI does *not* prove render correctness.
- **[headset-verified]** Means Liviu explicitly reported the result in the project brief, a commit message, or the current instruction. It is not an instrumented laboratory measurement.
- **[estimated]** Means new design, predicted performance, mathematical consequence, or test criterion not yet observed in a production headset.
- **[from memory, unverified]** Means recollection for which an exact repository log/run is not established. No such claim is used as a foundation for a safety-critical design decision.

## 5. Proposed architecture and immutable geometry contract

### 5.1 Frame timeline / family roles
**[estimated]** Each OpenXR frame, after one `xrWaitFrame` / prediction, capture one immutable `TriFrame{generation,drawSerial,xrFrameId,predictedDisplayTime,headPose,eyePoses[2],P_eyeBase[2],P_centreBase, gazeRay, eyeCrops[2], viewStates[3], jitter[3], targetIds[3], sourceDepthDescriptor}`. No mid-frame independent XR pose read is allowed. Render:
1. Role **C** (old slot0): **one low-res full-FOV centre background**, centre head-space position, fixed optical orientation defined by frozen head pose (the left-optical orientation may be retained only if consistently represented in `P_centreBase`); **own** FSceneViewFamily/FSceneViewState and distinct depth history.
2. Role **L** (old slot2): **true left optical camera**, focus crop of `P_eyeBase[0]`, tracked left-eye gaze ROI, primary singleton family, own view history.
3. Role **R** (old slot3): **true right optical camera**, focus crop of `P_eyeBase[1]`, tracked right-eye gaze ROI, primary singleton family, own view history.
4. Role1 remains a *constructed but unrendered* compatibility placeholder **only if** keeping Build51's four-constructor contract. Verify execution mask `0x0d`; eventual refactor to exactly three constructors is *not* part of the first build.
5. Both eyes' reconstructed backgrounds and their *real* fovea are composited into distinct OpenXR eye subimages from the **same** frame packet, then submitted with each eye's own `XrView` pose and FOV. CPU leases/GPU fences retire all source textures only after the actual copy/composite completes.

**[estimated]** Do not merge the left and right real foveae into one UE family on E1's assumption. A “3 views = 1 family” design contradicts performance/shading evidence. **[source-read]** Build51 `QuadViewFamilyRouting.hpp` / `NativeDelivery` offers a directly reusable native physical dispatch model.

### 5.2 Projection and proportions: the crucial invariant
**[estimated]** **Freeze raw per-eye asymmetric P_L and P_R before any mutation**. Let `E_L,E_R,E_C` be complete world-to-eye transforms (position *and* orientation), and let `P_C` be the centre projection covering the **union of both real eye frusta**, transformed into the same centre camera basis at *infinite rays*. Build union from 4 corner rays per eye using frozen OpenXR poses and pad for nonzero offset/near geometry **only within valid finite clip coverage**. A centre texture cannot actually encode surfaces outside its rendered FOV: fail or enlarge coverage, never clamp silently.

For a 3D homogeneous world point `X` seen by centre colour/depth:
```
qC = P_C * E_C * X
uvC = ((qC.x/qC.w + 1)/2, (1 - qC.y/qC.w)/2)
qL = Crop(P_L, cropL) * E_L * X
qR = Crop(P_R, cropR) * E_R * X
uvEyeFull(L/R) = Project(P_L/P_R * E_L/E_R * X)
```
The *same* `X` must land at `uvEyeFull` when the centre depth is reconstructed and projected into either eye; inside its own crop `uvCrop = (uvEyeFull - cropMin)/cropSize`. The compositor uses **full-eye destination UV** to index fovea blend, *never* a mutable source family crop UV. This is the definition of matching proportions: camera translation, cant, FOV, crop, output size, viewport origin, jitter and depth must agree. **[source-read]** `DuoViewGeometry.hpp::apply_foveal_crop` uses the valid x/y clip-row shifts without touching reversed-Z; `SurfaceGeometry.hpp` exposes row-major column-vector conversion for the surface warp.

**[estimated]** Pixel example at 72-mm physical IPD: each eye is roughly 36 mm from the midpoint (actual frozen tracked pose wins). At 0.5 m fronto-parallel distance, centre→eye shift corresponds to **0.036/0.5 = 0.072 tangent units**, substantial at a sharp fovea border; at 2m it is 0.018; the optical cant/eye FOV makes an assumed fixed pixel offset wrong. Head-scale/UE world-to-metres must be applied **once**, and user-configurable XYZ scale must affect centre and eyes under one policy. **[source-read]** prior PSVR2 Mono alignment -1.5 canceled the ~2m Mono convergence bias, but **[estimated]** it must be **OFF** for this physically correct true-stereo mode. Enforce 72 mm *calibration/default* in UI; trust runtime tracked eye transforms for live reconstruction rather than hardcoding 36mm in all frames.

### 5.3 Source depth and motion format
**[estimated]** Use **centre family's exact depth corresponding to its colour**. Preferred path: capture live centre's D3D12 depth into an explicitly tagged **R32_FLOAT** normalized device-depth texture, copying/reinterpreting DSV/NGX input according to the actual resource format/state (no blind DSV sampling or illegal depth copy). NGX DLSS SR input depth is suitable **only if** centre DLSS evaluation and its input `Depth` resource can be authenticated to `TriFrame/roleC/scene target/same producer frame`. Retrieve from NGX parameters: `Depth`, render width/height, depth viewport offset and extent, output dimensions, `Jitter.Offset.X/Y`, feature reset, flags, depth-to-NDC convention, and optional motion vectors. Capture on the appropriate RHI queue and hold resources to a GPU fence; raw device resource pointers have no eye identity.

**[source-read]** CI48 DLSS research explicitly warns Cheeky's `fg_publish_ngx` had no direct frame ticket; CI73 review likewise says current RHI packet + equal sizes does not prove a DLSS evaluation's view. **[estimated]** Implement binding at *producing* evaluation with a unique role-scoped render command-list token and freeze its P (jittered/unjittered) and transform; else mark centre depth unavailable and fail tri-mode frame (or fall back to stable Mono mode at transition boundary). Do not patch in old right-eye/left-eye geometry or assume a DLSS fovea input.

**[source-read]** `DuoViewSurfaceReproject.hlsl::MeshPoint` converts `(deviceDepth-rangeMin)/(rangeMax-rangeMin)`, inverts `SourceEyeFromClip`, and verifies positive camera Z; `SurfaceGeometry.hpp::build` infers reversed depth from projection derivative. **[estimated]** Verify against known test values: 1 near / 0 far *when* reversed-Z actually selected, no unmotivated `1-depth` flip; keep raw depth viewport range, exact projection `A,B,C,D`, UE world units and clear-depth handling explicit. DLSS *input* render resolution/subrect is not necessarily eye output resolution or fovea size; map all coordinates by pixel centers, not guesses.

### 5.4 Surface synthesis, holes and compositing
**[estimated]** Recommend **forward depth-mesh/splat** to each eye at low-res periphery, with per-pixel hardware Z ownership and discontinuity cuts; use `SurfaceGeometry.hpp` / `DuoViewSurfaceReproject.hlsl` as source-read prototypes. Avoid global backward-search screen displacement: at disocclusions it has no unique source surface and old inversions already caused unstable owners. A small inverse/gather clean-up may be useful **only after** splat coverage is proved, and must never sample a different eye's native colour.
- **[estimated]** Project centre depth triangles into each *full-eye target* using `P_eyeBase`, `E_eye`; valid triangles carry *centre* source colour UV and occlusion confidence. Reject triangles straddling foreground/background depth discontinuities; z-test surface ownership rather than comparing single-pixel depth.
- **[source-read]** CI82's coarse same-source connected fill rasterizes a background stretch behind measured surfaces and passed a WARP fixture; **[estimated]** use it, if needed, strictly for disocclusions, tagged low-confidence and constrained to periphery. Never stretch foreground hands. Do not interpolate a material that was never seen and call it real texture.
- **[estimated]** Composite **per-eye periphery reconstructed → each eye's REAL sharp fovea → feather/tonemap/swapchain**. Within true fovea `weight=1`, therefore synthetic RGB is never visible. Border feather may expose centre errors: define blend band *inside* the native fovea, default narrow and adjustable. Real eye always wins at its inner edge. Reject unsupported holes in the band (e.g. fade to measured native colour, expand actual foveal crop, or declare failure); never introduce the other eye as fallback. Preserve source's exposure/colour space, then apply a consistent output transfer.
- **[estimated]** Full scene + viewmodel complication: if the centre camera renders a hand as a *different camera projection* than real eye, the feather shows both surfaces. Better explicit center-pass viewmodel mask (or same-world camera projection handling) plus a test that real fovea covers *all* viewmodel pixels when gazing at a hand; don't hide it by making hands Mono. No unsupported claim that all hands can be completely excluded without a UE show-flag experiment.

### 5.5 Gaze, DLSS, NR, history, submission
**[source-read]** `quadview/QuadViewPSVR2Gaze.hpp::Reader::read_ray()` provides the single recovered head-space calibrated ray. `QuadViewGaze.hpp` maps it independently through both frozen eye rotations and full-eye projections. **[estimated]** Read gaze **once per `TriFrame`**; calculate two *different* eye crops; clamp their centers so the entire fixed fovea fits the visible eye. Store crop values and raw projection hashes with output. Eye gaze changes require resetting/updating corresponding per-role TAA/DLSS histories if the changing crop invalidates temporal reprojection; never share the three `FSceneViewState` pointers. Distinct DLSS evaluation identities/NR histories for C,L,R must be linked to the same frame; do not force NR in initial geometric build. **[source-read]** B2 review confirms the four constructed view-state histories, but also that unused view1 stays allocated; role1 can be retired later if evidence justifies it.

**[estimated]** OpenXR: copy each final eye colour into the correct swapchain subimage using the same frame serial; submit `XrCompositionLayerProjectionView` with *each* runtime eye's own pose/FOV; original left/right quad output rectangles are not substitutes for the runtime's compositor geometry. Explicitly prohibit Mono Eye Alignment=-1.5 for this mode. Reset generation on gaze-provider change, IPD/world scale change, resolution, DLSS feature reset, load/travel, and renderer mode toggle.

## 7. Performance model — don't promise a speed-up until measured
**[headset-verified, brief]** Small-view fixed GPU cost ~7ms per *new family* and ~2.5ms for another view in an existing family, reported at 200×200. 3.8k×3.1k Native Stereo 24fps, B3 28–30fps broken, quad 25–30fps depending on scene/resolution. **[estimated]** Three singleton families imply ~3×7ms = **21ms of fixed-family work before substantial full-resolution pixel shading, depth processing, synthesis and compositor**. B3's 28–30fps means ~33–36ms *total* on its comparison scene; synthesis should add a measured positive GPU overhead. A target **~27–32fps** at 3.8k×3.1k is a *planning range only*, not a prediction with controlled error bars. At 120Hz, 30→120 requires reliable frame pacing, but we do not assume the mod itself supplies such a generator.

**[estimated]** Instrument separately and report median/p95 ms: **C/L/R UE GPU family**, prepass/Lumen/VSM/TSR/DLSS/NR per family, centre depth capture and barriers, two reprojection passes, hole fill, feather/composite, swapchain copy, and CPU GT/RT/RHI submission; show GPU utilization, VRAM resident, valid source frame ratio, dropped frames, gaze age, DLSS reset rate, depth valid coverage and border mismatch pixels. Always compare at same stationary test scene and resolution (200×200 fixed-cost and 3800×3100 real load), same game/UEVR/DLSS/NR flags, same native frame generation configuration. Stop if a supposed periphery reduction creates a full-size UE scene texture/hidden render family.
